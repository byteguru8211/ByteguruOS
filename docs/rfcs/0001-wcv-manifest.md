# RFC 0001: формат манифеста WinCompat (WCV), schema 1

Статус: принят и реализован (`src/wincompat/wcmgr/manifest.py`).
Источники истинности: код и тесты `tests/test_manifest.py`, а не этот документ —
расхождение считается дефектом документа.

## Мотивация

Запуск Windows-приложения — это сочетание бинарника, версии Wine, наборов системных
библиотек, графического пути, доступа к сети, файловому виду и политикам изоляции.
Если это хранится в голове пользователя или в README-инструкции, воспроизводимость
теряется: на двух одинаковых машинах приложение работает по-разному. Манифест
делает конфигурацию адресуемой, подпись — проверяемой, а уровень покрытия —
данным, а не мнением.

## Единица формата

Один файл TOML на приложение, расширение `.wcv`, имя = идентификатор приложения.
Каноническая сериализация (`dump_toml`) детерминирована: одинаковое содержание →
одинаковые байты, поэтому хэш манифеста годится как идентификатор версии политики.

## Секции и поля

### `[wcv]` — обязательная

| Ключ | Тип | Обязателен | Правило |
|---|---|---|---|
| `schema` | int | да | только `1`; другое значение — отказ |
| `id` | str | да | `[a-z0-9][a-z0-9._-]{1,63}` (латиница: идентификатор попадает в пути и юниты) |
| `name` | str | да | человеческое название, кириллица разрешена |
| `version` | str | да | версия приложения |
| `executable` | str | да | путь **внутри префикса**, `.exe` или `.msi`; абсолютный путь запрещён |
| `runner` | `wine` \| `kvm` \| `native` | да | способ исполнения |
| `expected_level` | `l0`…`l4` | да | заявленный уровень покрытия |
| `publisher` | str | нет | |
| `wine` | str | нет | фиксация версии Wine |
| `prefix` | str | нет | имя окружения; по умолчанию `id` |
| `tested` | bool | нет | подтверждён ли уровень прогонами (по умолчанию `false`) |
| `tested_notes` | str | нет | что именно проверяли |
| `installer_filename` | str | нет | |
| `installer_sha256` | str | нет | ровно 64 hex, строчными |
| `comments` | str/list | нет | только для человека, на поведение не влияет |

Значение `expected_level`:

- `l0` — не поддерживается (драйвер ядра, anti-cheat, DRM).
- `l1` — полноценная работа в WinCompat.
- `l2` — базовый сценарий: просмотр, печать, простые операции.
- `l3` — только через виртуальную машину.
- `l4` — только через перезагрузку в Windows на этом же диске.

### `[graph]`

`path`: `auto` (по умолчанию) | `dxvk` | `vkd3d` | `x11` | `glx`; `dxvk_version` —
строка. Путь выбирается осознанно: приложение с D3D9 без DXVK работает иначе, и это
должно быть зафиксировано, а не «как получится».

### `[drives]`

`mappings` — массив inline-таблиц `{ letter, kind, path, mode }`:

- `letter`: одна буква `C`–`Z`; `A`/`B` запрещены (исторические гибкие диски).
- `kind`: `prefix` (только для `C`), `bind`, `image` (`.img`/`.iso`).
- `mode`: `ro`/`rw`.
- `bind.path` — абсолютный POSIX-путь, без `..`, не совпадающий с системным корнем
  (`/`, `/etc`, `/home`, `/var`, `/usr`, `/dev`, `/proc`, `/sys`, `/root`, …) и не
  указывающий внутрь хранилища WinCompat.
- Литера не может быть назначена дважды; `C` обязана быть префиксом.

### `[network]`

`mode`: `blocked` (по умолчанию) | `allowlist`. **`open` запрещён** в подписанных
манифестах: он обходил бы смысл изоляции. `domains` допустимы только вместе с
`allowlist`. `ports` — `{ proto = "tcp"|"udp", port = 1..65535 }`.

Исполнение `allowlist` обеспечивает прокси `wc-net`; сам по себе AppArmor списка
доменов не фильтрует — об этом манифест честно предупреждает при построении
политики.

### `[devices]`

`audio` (bool, по умолчанию `true`), `camera` (`false`), `printers`
(`none` | `queue-only` | `direct`, по умолчанию `queue-only`), `usb` — массив
`{ vendor, product, description }` с 4-hex ID. Без `usb` прямой доступ к
`/dev/bus/usb/**` запрещён профилем.

### `[filesystem]`

`visible` / `hidden` — списки абсолютных путей. `hidden` имеет приоритет над
`visible`: скрытый путь запрещён, даже если попадает в разрешённый корень.
Подстановка `%USER%` раскрывается из имени сеанса; если путь содержит `%USER%`, а
сеанс не передан — запуск отклоняется, а не монтируется с пустым именем.

### `[security]`

`apparmor`: `enforce` (по умолчанию) | `complain` | `off`; `seccomp`: `strict`
(по умолчанию) | `basic` | `off`; `no_new_privs`: по умолчанию `true`, значение
`false` **запрещено**. Оба механизма одновременно в `off` — отказ: запуск возможен
только с явным `--no-sandbox` в отладке.

### `[integration]`

`menu` (bool) — показывать ли в лаунчере; `mime` — список поддерживаемых MIME-типов
для «Открыть в…».

### `[update]`

`policy`: `disabled` (по умолчанию) | `manual` | `auto`. Обновление Windows-
приложения может сломать проверенный манифест, поэтому по умолчанию оно запрещено,
а новый набор файлов приходит как новая версия WCV.

## Незнакомое — ошибка

Любой неизвестный ключ в любой секции отвергается. Причина не стилистическая:
`networke = "allowlist"` означало бы «сети нет», а `scURITY` — «изоляции нет».
Тихая победа по опечатке в манифесте безопасности недопустима.

## Управление версиями

- `schema` — формат файла.
- `fingerprint()` — хэш содержания политики; меняется при любой правке.
- Манифест копируется в окружение приложения при установке; версия окружения
  хранит копию и хэш, откат возвращает ровно ту политику, с которой был прогон.

## Публичный уровень покрытия

Реестр совместимости публикует **подтверждённый** уровень: максимум успешных
прогонов, где `l1 > l2 > l0`; прогоны `l3`/`l4` (ВМ и соседняя Windows) не
засчитываются как работа Wine-слоя. Поэтому:

- манифест с `expected_level = l1` и без прогонов отображается как «не проверено»;
- прогон с падением понижает опубликованный уровень до `l0`, пока не появится
  успешный.

## Пример

См. `data/wincompat/1c-client-83.wcv` (полный) и
`data/wincompat/notepad-plus.wcv` (минимальный с безопасными значениями по умолчанию).

## Неопределённые места (следующие ревизии)

- Подпись манифеста и цепочка доверия ключей — не реализованы.
- Схема для многотомных установок (`installer.part2`) — не определена.
- Миграция конфигурации между версиями Wine — только проектируется (`wc-registry`).
