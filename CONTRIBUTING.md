# Как участвовать

## Окружение разработки

Нужен Python 3.11+; Linux не обязателен для тестов ядра подсистем, но обязателен
для сборки образа и проверки интерфейса.

```sh
python -m venv .venv && . .venv/bin/activate
pip install pytest
pytest -q
```

Запуск подсистем локально (без установки в систему):

```sh
PYTHONPATH=src/wincompat:src/installer python -m wcmgr.cli check data/wincompat
PYTHONPATH=src/installer python -m bginstaller.cli plan --disk-file tests/fixtures/lsblk-dualboot.json
PYTHONPATH=src/bytegurud:src/wincompat python -m bgd.cli --wcv-dir data/wincompat --registry /tmp/r.db apps
```

## Правила кода

- **Комментарий объясняет почему, а не что.** Строки вида `# увеличиваем счётчик`
  не нужны: имена обязаны справляться сами.
- **Никаких выдуманных интерфейсов.** Флаг, пакет, API или поле схемы, которых не
  существует, — это не «заготовка», а будущая авария. Проверить дешевле, чем
  чинить: имена пакетов — `python3 build/scripts/check-package-names.py`
  (сверка с индексом trixie), опции и команды — запуск против живого кода,
  конфигурационные ключи — чтение парсера, а не памяти.
  Исторический маркер `ВЕРИФИЦИРОВАТЬ: …` из кода убран: он появился, когда
  композитор ни разу не собирался, а теперь сборка с `-Werror` на прототипах,
  прогоны в headless-сеансе и тесты сокета проверяют это сами.
- **Чистые функции для принятия решений, исполнение — отдельно.** Планировщик
  разметки, генератор политик и сборщик команд ничего не делают сами; исполнение
  требует явного `--apply`/`--run` и происходит в одном месте.
- **Неизвестные данные — риск, а не разрешение.** Неизвестный ключ манифеста,
  незнакомая настройка, неизвестное состояние «быстрого запуска» Windows
  останавливают операцию или уводят её в предупреждение.
- **Линейки LF, UTF-8.** См. `.editorconfig` и `.gitattributes`; CRLF в shell- и C-файлах ломает сборку на Linux-раннере.

## Тесты

- Каждый новый модуль — с тестами в `tests/`, включая негативные: неверный ввод
  обязан быть отвергнут с объяснимым сообщением.
- Фикстуры вывода системных утилит кладутся в `tests/fixtures/` как есть,
  с комментариями, на какой версии утилиты они получены.
- Тест, который нельзя запустить без root/железа, помечается `@pytest.mark.skipif`
  с причиной — но не удаляется.
- Есть три уровня проверки, и они не заменяют друг друга: `pytest` (логика,
  работает везде), `build/scripts/desktop-shot.sh` (интерфейс — кадром,
  потому что «рендерится» и «рендерится как задумано» глазами не различаются)
  и прогоны образа в QEMU (загрузка и установка).
- Изменения в `bin/` и `docs/man/` проверяются тестами на упаковку: каждый
  скрипт и каждая справочная страница обязаны быть указаны в `debian/*.install`,
  иначе в образе их просто нет.

## Процесс изменений

1. Ветка от `main`, имя по смыслу: `wincompat/network-proxy`, `installer/esp-reuse`.
2. PR обязан содержать: что меняется, почему, **что проверено и чем**, а что
   осталось непроверенным. Формулировка «должно работать» не принимается.
3. CI: `tests.yml` (pytest) и `iso.yml` (сборка образа, прогон в QEMU,
   shellcheck и `.desktop`). `iso.yml` больше не информативный: сборка
   проходит, а `boot-smoke-test` проверяет, что образ действительно даёт
   рабочий сеанс.
4. Изменения в архитектуре (уровень решений К1–К12) — только через RFC в
   `docs/rfcs/`, с явным указанием, что ломается у существующих пользователей.
5. Справочные страницы и документация меняются вместе с кодом, а не после:
   `docs/USER.md` для того, кто сел за стол, `docs/ADMIN.md` для того, кто
   его обслуживает, `docs/man/*` для терминала. Расхождение считается дефектом
   документации.

## Что сейчас особенно нужно

- Прогнать `wcmgr check` и план запуска против настоящего Wine 9/10 в Debian 13 и
  прислать вывод: это первые данные для реестра совместимости.
- Установка на **физический** диск и загрузка с него на реальном железе:
  end-to-end прогон в QEMU есть, но поведение прошивки при записи NVRAM он
  не проверяет.
- XWayland: самый большой функциональный пробел. Требует отдельного слоя
  decorations для x11-поверхностей, поэтому не сделан «между делом».
- Greeter: сейчас вход — autologin через getty, пароля при входе нет.
- Проверка интерфейса на HiDPI и на нескольких мониторах: протоколы
  `fractional-scale`, `viewporter` и `output-management` отданы, а живого
  подтверждения масштаба нет.
