# ByteguruOS

Открытая операционная система общего назначения, спроектированная
вокруг двух обязанностей, которые обычно оставляют на пользователя:

1. **Запускать Windows-приложения как штатный сценарий.** Подсистема WinCompat
   даёт каждому приложению изолированное окружение, манифест политики и честный
   уровень покрытия вместо «попробуйте Wine, может сработать».
2. **Уживаться с Windows на одном компьютере.** Двухзагрузочный режим —
   поддерживаемая конфигурация с восстановлением загрузчика и предсказуемой
   политикой для NTFS, а не народный рецепт из вики.

**Статус проекта.** Это независимая личная разработка с открытым кодом. ByteguruOS
не является продуктом какой-либо государственной программы, не аттестован, не
включён ни в какие реестры программного обеспечения и не имеет официальной
поддержки. Названия сторонних продуктов и дистрибутивов упоминаются только как
технологические ссылки; товарные знаки принадлежат их владельцам.

Полный план разработки с архитектурными решениями К1–К12: [docs/ByteguruOS-plan.docx](docs/ByteguruOS-plan.docx).
Что уже написано кодом, а что ещё нет — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

сейчас закрыты маркерами `ВЕРИФИЦИРОВАТЬ`.

## Что уже нельзя назвать макетом

- **Манифест приложения.** Неизвестный ключ — ошибка, а не тихо проигнорированная
  настройка; сеть `open` запрещена; системные корни нельзя открыть как литеру;
  `no_new_privs=false` не проходит. Опечатка в `networke` не превратится в
  «сеть открыта».
- **Уровень покрытия подтверждается прогонами.** Заявленный в манифесте L1
  публикуется как «не проверено», пока удачный прогон не попал в реестр. Примеры
  манифестов в `data/wincompat/` намеренно имеют `tested = false`.
- **Разметка считается по непрерывным областям.** Сумма свободных промежутков не
  равна доступному месту: раздел обязан быть непрерывным, и планировщик это
  учитывает, иначе 1 ГиБ щель «превращается» в несуществующее место.

## Структура

```
build/        конвейер сборки образа (live-build, defconfig ядра, Dockerfile сборки)
iso/          overlay для live-образа: утилиты загрузки, политики монтирования
data/         примеры манифестов WCV, .desktop-файлы, systemd-юниты, сеанс
src/wincompat/ подсистема WinCompat: манифесты, окружения, изоляция, запуск
src/installer/  установщик: разметка, проверки, ремонт EFI, политика часов
src/bytegurud/  демон единой модели приложений
src/shell/      оболочка: модель панели, настройки, мастер, GTK-слой
src/compositor/ композитор bgwl на wlroots
tests/          pytest-набор и фикстуры вывода системных утилит
docs/           план (.docx), архитектура, инструкции, RFC
```

## Сборка и проверка

Тесты (любая ОС, нужен Python 3.11+):

```sh
python -m venv .venv && . .venv/bin/activate
pip install pytest
pytest -q
```

CLI работает на любой машине — план запуска печатается, исполнение требует Linux:

```sh
PYTHONPATH=src/wincompat:src/installer python -m wcmgr.cli check data/wincompat
PYTHONPATH=src/wincompat:src/installer python -m wcmgr.cli --storage /tmp/wcv --registry /tmp/reg.db install data/wincompat/notepad-plus.wcv
PYTHONPATH=src/installer python -m bginstaller.cli plan --disk-file tests/fixtures/lsblk-dualboot.json --profile office-dualboot
```

**Образ ISO собирается только в Linux-окружении, и в этом репозитории — только в
CI** (GitHub Actions, контейнер `debian:trixie`). На Windows его собрать физически
нельзя: нет live-build, xorriso, grub-mkimage и loop-устройств. Порядок действий и
скачивание артефакта описаны в [docs/VIRTUALBOX.md](docs/VIRTUALBOX.md).
