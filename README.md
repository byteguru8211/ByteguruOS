# ByteguruOS

Дистрибутив Linux с собственным оконным окружением. Не «ещё один стол с
наклейкой», а система, где свои композитор, оболочка, установщик и конвейер
сборки образа.

Три вещи, ради которых затевался проект:

1. **Свой оконный стол.** Композитор `bgwl` на wlroots: потоки (не воркспейсы
   с перекладыванием окон, а деревья сцены, переключаемые за O(1)), тайлинг
   тремя раскладками, блокировка сеанса, простой с двухступенчатым отключением
   экрана — и сокет управления, из-за которого панель, `bgctl` и палитра видят
   одно и то же состояние.
2. **Строка Guru вместо меню.** `Super+Esc` принимает и приложения, и потоки,
   и действия сеанса: «разложить тайлом», «поток 3», «заблокировать», «светлая
   тема». Одна строка вместо обхода четырёх меню настроек.
3. **Уживаться с Windows, но не ради Windows.** Двухзагрузка — поддерживаемая
   конфигурация: сжатие NTFS только после проверки тома, ремонт загрузочной
   записи после обновлений Windows, согласованная политика часов. Подсистема
   WinCompat (запуск Windows-программ) по умолчанию **выключена** и включается
   человеком, когда она реально нужна.

**Статус проекта.** Это независимая личная разработка с открытым кодом. ByteguruOS
не является продуктом какой-либо государственной программы, не аттестован, не
включён ни в какие реестры программного обеспечения и не имеет официальной
поддержки. Названия сторонних продуктов и дистрибутивов упоминаются только как
технологические ссылки; товарные знаки принадлежат их владельцам.

Полный план разработки с архитектурными решениями К1–К12: [docs/ByteguruOS-plan.docx](docs/ByteguruOS-plan.docx).
Что уже написано кодом, а что ещё нет — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Текущее состояние

Система собирается, загружается и даёт рабочий сеанс. Образ проверяется
двумя способами: статически (какой rootfs получился) и прогоном в QEMU с
само-проверкой live-сессии.

| Компонент | Код | Проверено |
|---|---|---|
| Схема и валидация манифестов WCV | `src/wincompat/wcmgr/manifest.py` | 14 тестов |
| Окружения, реестр совместимости, изоляция, уровни L0–L4 | `src/wincompat/wcmgr/` | 41 тест |
| CLI `wcmgr` | `src/wincompat/wcmgr/cli.py` | 16 тестов |
| Планировщик разметки, dual boot, исполнение плана | `src/installer/bginstaller/` | 48 тестов |
| Окно установщика | `src/installer/bginstaller/ui/` | снимки экрана в headless-сеансе |
| Демон `bytegurud` | `src/bytegurud/bgd/` | 16 тестов |
| Модель оболочки: настройки, темы, палитра, системные индикаторы | `src/shell/bgshell/` | 48 тестов |
| GTK-интерфейс: панель, Guru Line, лаунчер, настройки, локер, уведомления | `src/shell/bgshell/ui/` | снимки экрана в headless-сеансе |
| Композитор `bgwl` (C/wlroots 0.18) | `src/compositor/` | собран; 6 интеграционных тестов против сокета управления; снимки экрана |
| Пакеты `.deb` | `debian/` | собираются (`dpkg-buildpackage`) |
| Конвейер сборки ISO | `build/`, `iso/` | образ 1.0 ГБ собран; QEMU доходит до `graphical.target` |

Что ещё не подтверждено: загрузка на реальном железе и в UEFI-прошивке,
настоящий Wine против реальных приложений, XWayland, экран приветствия с
паролем, immutable root и A/B-обновления.

## Что уже нельзя назвать макетом

- **Манифест приложения.** Неизвестный ключ — ошибка, а не тихо проигнорированная
  настройка; сеть `open` запрещена; системные корни нельзя открыть как литеру;
  `no_new_privs=false` не проходит. Опечатка в `networke` не превратится в
  «сеть открыта».
- **Уровень покрытия подтверждается прогонами.** Заявленный в манифесте L1
  публикуется как «не проверено», пока удачный прогон не попал в реестр. Примеры
  манифестов в `data/wincompat/` намеренно имеют `tested = false`.
- **Разметка считается по непрерывным областям.** Сумма свободных промежутков не
  равна доступному месту: раздел обязан быть непрерывным, и планировщик это
  учитывает, иначе 1 ГиБ щель «превращается» в несуществующее место.
- **План установки исполняется, а не печатается.** Каждое действие собирается в
  обычные утилиты образа (`parted`, `mkfs.*`, `rsync`, `grub-install`,
  `efibootmgr`); пароль уходит в stdin `chpasswd`, а не в список аргументов,
  где его видно в `/proc`.
- **Профиль выбирает диск.** Раньше планировщик требовал ровно размеры профиля
  и отказывал 24-ГиБ диску — то есть любой виртуалке. Теперь разделы
  уменьшаются, но не ниже минимума, при котором обновление не встанет.
- **Оболочка читает состояние из одного места.** Сокет управления композитора
  отдаёт JSON и события; панель, `bgctl` и Guru Line не могут разойтись,
  потому что спрашивают одного и того же.
- **Образ проверяется загрузкой.** `boot-smoke-test.sh` монтирует ISO, берёт из
  него ядро с initrd и ждёт на консоли строки `BYTEGURU-SESSION-OK` от
  само-проверки live-сеанса.

## Структура

```
build/        конвейер сборки образа (live-build, defconfig ядра, Dockerfile сборки)
iso/          overlay для live-образа: утилиты загрузки, политики монтирования,
              само-проверка сеанса
data/         .desktop-файлы, systemd-юниты, wayland-сеанс, примеры манифестов WCV
src/compositor/ композитор bgwl на wlroots: потоки, тайлинг, сеанс, сокет управления
src/shell/      оболочка: панель, Guru Line, лаунчер, настройки, локер, уведомления
src/bytegurud/  демон единой модели приложений
src/installer/  установщик: разметка, исполнение плана, GTK-окно, ремонт EFI, часы
src/wincompat/  подсистема WinCompat (опциональная): манифесты, окружения, изоляция
bin/          точки входа, которые устанавливаются в /usr/bin
tests/          pytest-набор и фикстуры вывода системных утилит
docs/           план (.docx), архитектура, инструкции, RFC
```

## Сборка и проверка

Тесты (любая ОС, нужен Python 3.11+):

```sh
python -m venv .venv && . .venv/bin/activate
pip install pytest
pytest -q
```

CLI работает на любой машине — план запуска печатается, исполнение требует Linux:

```sh
PYTHONPATH=src/wincompat:src/installer python -m wcmgr.cli check data/wincompat
PYTHONPATH=src/wincompat:src/installer python -m wcmgr.cli --storage /tmp/wcv --registry /tmp/reg.db install data/wincompat/notepad-plus.wcv
PYTHONPATH=src/installer python -m bginstaller.cli plan --disk-file tests/fixtures/lsblk-dualboot.json
```

## Сборка образа

Разработка идёт в Linux, и образ собирается локально — для этого нужны
live-build, debootstrap, xorriso и root (loop-устройства):

```sh
sudo apt-get install -y live-build debootstrap xorriso squashfs-tools \
  meson ninja-build pkg-config libwlroots-0.18-dev dpkg-dev debhelper
bash build/scripts/build-packages.sh          # .deb в build/live/config/packages.chroot/
sudo bash build/scripts/build-iso.sh          # образ в build/out/
sudo bash build/scripts/boot-smoke-test.sh    # прогон в QEMU: дошёл ли сеанс
sudo bash build/scripts/install-smoke-test.sh # установка на диск + загрузка с него
```

Порядок сборки важен: `build-iso.sh` берёт `.deb` из `packages.chroot/` и не
пересобирает их, поэтому после правки в `src/` нужен `build-packages.sh`.
В CI то же самое делают job'ы `iso-amd64`, `boot-smoke-test` и `lint-shell`;
на Windows образ собрать нельзя — нет live-build, grub-mkimage и loop-устройств.

страницы с кодом считается дефектом страницы.
